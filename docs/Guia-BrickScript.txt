=============================================================
          PROYECTO: BrickScript - Un Lenguaje para Juegos Retro
=============================================================

BrickScript es un lenguaje de programacion simple (un "DSL" o Lenguaje de Dominio Especifico) disenado para crear juegos clasicos de estilo "Brick Game", como Tetris y Snake.

Este proyecto incluye el compilador que traduce el codigo BrickScript a un formato que la computadora entiende, y el motor de juego que lo ejecuta.

El runtime usa Python 2.7 con Tkinter y funciona en Windows y Linux.
Los pasos de instalacion estan en docs/Instalacion.txt.

-------------------------------------------------------------
                      COMO JUGAR
-------------------------------------------------------------

Para compilar y ejecutar un juego, hemos creado un script que hace todo el trabajo por ti.

1. Abre una terminal en la carpeta raiz del proyecto.

2. Ejecuta el script de tu sistema seguido del nombre del juego (el nombre
   del archivo en games/ sin la extension .brick) o de su numero en el menu:

   WINDOWS (cmd.exe):          LINUX:
   jugar.bat snake             ./jugar.sh snake
   jugar.bat tetris_reborn     ./jugar.sh tetris_reborn

   Si no indicas ningun juego, el script muestra un menu con todos los
   juegos que encuentra en games/.

El script primero compilara el archivo .brick correspondiente. Si la compilacion es exitosa, el juego se iniciara automaticamente.

Para salir del juego, cierra la ventana.


-------------------------------------------------------------
                 SINTAXIS DE BRICKSCRIPT
-------------------------------------------------------------

El lenguaje se basa en bloques de comandos simples y faciles de entender.

--- COMANDOS GENERALES ---

* GAME_TYPE [TIPO_DE_JUEGO]
    Define que logica usara el motor. Obligatorio.
    Ej: GAME_TYPE TETRIS
    Ej: GAME_TYPE SNAKE

* GAME_GRID (ANCHO, ALTO)
    Establece el tamano del area de juego.
    Ej: GAME_GRID (10, 20)

* DEFINE SHAPE [NOMBRE_PIEZA]: ... END
    Define una forma geometrica con uno o mas estados (para rotaciones).
    Ej: DEFINE SHAPE T_PIEZA: STATE 1: [0,1,0][1,1,1][0,0,0] END
    Opcionalmente, antes de los dos puntos, se puede indicar el color
    (por defecto CYAN) y la probabilidad de aparecer (por defecto 10):
    Ej: DEFINE SHAPE T_PIEZA COLOR PURPLE CHANCE 10: STATE 1: [0,1,0][1,1,1][0,0,0] END

* LEVELS: ... END
    Bloque opcional que declara los niveles de dificultad del juego. Cada nivel
    lleva sus modificadores; START indica con cual arranca la partida.

    Ej: LEVELS:
          START: NYAN_CAT
          LEVEL BABY:
            TICK 0.15
          END
          LEVEL NYAN_CAT:
            TICK 0.06
          END
        END

    - TICK <real>: segundos entre cada tick del juego. Si un nivel no lo declara,
      el juego conserva su velocidad por defecto (Snake 0.15, Tetris 0.4).
    - MUSIC <cancion>: tema que arranca con ese nivel. Debe ser una cancion
      declarada con DEFINE SONG en el mismo archivo; si no existe, el compilador
      avisa al compilar. Si el nivel no lo declara, manda el PLAY_MUSIC que pone
      el propio archivo (o el silencio).
    - START: <nombre>: nivel con el que arranca la partida. Sin START se usa el
      primer nivel declarado.
    - Los nombres de nivel se escriben en MAYUSCULAS porque el lexer solo
      reconoce identificadores en mayusculas.
    - Si el archivo no declara LEVELS, el motor asume el nivel BABY con la
      configuracion por defecto del juego. Por eso los .brick clasicos siguen
      funcionando sin cambios.

    Cuando el archivo declara dos o mas niveles, el juego muestra un menu de
    botones antes de empezar. Cada boton se puede hacer clic o elegir con su
    numero (1, 2, 3...) segun el orden en que estan declarados los niveles. El
    texto del boton sale del nombre: NYAN_CAT se muestra como 'Nyan Cat'.

* ACCIONES DE SONIDO (en cualquier evento)
    PLAY_MUSIC <cancion>   arranca la cancion en bucle
    PLAY_EFFECT <efecto>   suena una vez y NO corta la musica
    STOP_MUSIC             corta la musica

    Ej:
        ON EAT_FOOD:
          INCREASE_SCORE 10
          PLAY_EFFECT COMER
        END

        ON GAME_OVER:
          PLAY_EFFECT MORIR
        END

    Un efecto nunca interrumpe la musica de fondo: van por canales separados.
    Si el nombre no existe, el juego no se rompe, suena mudo. El motor emite
    ON GAME_OVER una sola vez, tanto si choca con la pared como si se come a si
    misma, asi que ahi va el efecto de morir.

--- SINTAXIS PARA TETRIS ---

Eventos disponibles: ON START, ON TICK, ON LINE_CLEAR, ON KEY_UP, ON KEY_DOWN, ON KEY_LEFT, ON KEY_RIGHT
En variantes extendidas (ej. tetris_reborn.brick con ON ROTATE, ON EXPLOSION,
ON GAME_OVER): el motor además dispara ON_PIECE_LAND al fijarse cada pieza,
por lo que cualquier .brick puede definirlo aunque reborn no lo use.

Acciones comunes:
* SPAWN RANDOM_SHAPE
* MOVE CURRENT_PIEZA [LEFT | RIGHT | DOWN]
* ROTATE CURRENT_PIEZA
* INCREASE_SCORE [PUNTOS]
* En variantes extendidas: PLAY_MUSIC [TEMA], PLAY_EFFECT [EFECTO], STOP_MUSIC

--- SINTAXIS PARA SNAKE ---

Eventos disponibles: ON START, ON TICK, ON EAT_FOOD, ON COLLISION_WALL, ON COLLISION_SELF, ON KEY_UP, ON KEY_DOWN, ON KEY_LEFT, ON KEY_RIGHT

Acciones comunes:
* SPAWN PLAYER AT (X, Y)
* SPAWN FOOD AT RANDOM
* MOVE PLAYER FORWARD
* SET_DIRECTION [UP | DOWN | LEFT | RIGHT]
* INCREASE_SCORE [PUNTOS]
* GROW PLAYER [CANTIDAD]
* GAME_OVER
